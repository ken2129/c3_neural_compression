## 記録の約束

1. 単位は「研究上の問い」。Issue番号は過去の参照先との対応を保つために使う。
2. 各記録に「目的」「計画」「結果」「解釈」「判断・次の作業」「出典」を置く。
3. 更新には日付と出典を付ける。「決定済み」「提案」「観測」「未確認」を区別する。
4. 結果には code/config/checkpoint hash、manifest、run ID、対象画像、rate、評価器、成果物参照、検証範囲を残す。数値を確認できない場合は空欄を推測で埋めない。
5. 「ファイルがある」「loadできた」「推論できた」「全画像の評価が完了した」「成果物validate済み」を分けて記録する。
6. 失敗・中断attemptを保持し、成功画像だけを選んだAPや途中結果を完成した比較として扱わない。
7. 実験・保存先・予算の拡大は、記録更新だけでは承認されたことにならない。
8. 認証情報、非公開ホスト名、個人用接続情報を記録しない。実行環境は「主比較環境」等の役割名で示す。

## 更新するタイミング

- 実験前: 問い、仮説、比較条件、固定manifest、実行範囲・予算を確定して計画を更新する。
- 各runの終了時: 成功・失敗・中断を含め、結果と成果物／ログの参照、検証範囲を追加する。
- 解釈や次の判断が変わった時: 日付、根拠、変更理由、次に行うことを記録する。
- 進捗報告用の資料はこの記録をもとに別途まとめる。記録の更新を理由に報告資料を自動作成しない。

今後の更新では、結論が変わった理由も日付付きで残す。
現時点では新しい機構を追加する前に、現在の方式がどの条件で役立つかを確認する。
最適化予算、物体サイズ、domain shift、ROI、distillation、task-aware bit allocationなどの候補は未選定であり、本記録はその実行計画を追加しない。

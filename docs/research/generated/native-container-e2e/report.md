# Native container 単一GPU E2E確認

Issue #113の承認範囲で、既存依存だけを使ったJAXの小規模な実行経路を確認した。C3の学習・ベンチマーク・性能評価は実施していない。

## 再現

リポジトリのルートで次を実行する（GPU 0を1台だけ使用）。

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 /usr/local/bin/python docs/research/generated/native-container-e2e/check.py
```

[スクリプト](check.py)はJAX import前にGPUメモリ事前確保を無効化し、CUDAバックエンドを指定する。GPUバックエンド・可視デバイス数1・出力の配置を検証し、CPUへのフォールバックを許さない。乱数seed 113のfloat32入力を用い、独立したNumPy float64行列積と比較する。入力転送完了後に計測を開始し、`block_until_ready()`で計算完了を待つ。再実行すると隣の[result.json](result.json)を上書きする。

## 実測結果と実際の検証

- GPU: NVIDIA GeForce GTX 1080、論理ID 0、GPU数1、バックエンド `gpu`。
- 行列: (32, 32) × (32, 32)。最大絶対誤差 `5.270694112269325e-07`、許容値 `1e-4`。非有限値なし。判定成功、プロセス終了コード0。
- 計算時間: `0.5754531295970082` 秒。初回コンパイルとディスパッチから同期完了までを含み、入力転送・NumPy参照計算は除く。
- Python 3.10.22 / JAX 0.4.24 / jaxlib 0.4.24 / NumPy 1.25.2。
- GPU計算は1回のみ実行。その後CPUだけでPython構文を解析し、保存JSONのGPU数・バックエンド・誤差・許容値・形状・正の時間・事前確保無効の整合性をassertで確認した（成功）。
